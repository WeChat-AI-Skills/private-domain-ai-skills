# 规则卡模板与置信度

## 1. 模板

```yaml
id: rule-2026-11-014
title: 问“不勒腰”时优先宽腰头款
version: 1
status: shadow            # draft / shadow / active / deprecated
owner: 店长王
created_at: 2026-11-13
触发:
  all:
    - 客户问句包含: ["不勒腰", "勒腰", "腰紧"]
    - 预算 >= 300
  none:
    - 客户明确要低腰
动作:
  - 优先推荐: 高腰宽腰头款
  - 附: 腰头特写 1 张
话术: "这版腰头加宽 2 厘米，坐着不勒；您平时穿 M 还是 L？"
例外:
  - 客户要低腰
  - 预算 < 300
  - 客户在投诉
证据:
  - case_11: 11-03 客户 A，推荐后下单
  - case_12: 11-06 客户 B，推荐后下单
  - case_13: 11-09 客户 C，流失（要低腰）→ 已写成例外
置信度: medium
观察期: 2026-11-13 至 2026-11-27
指标: 推荐后回复率、下单率、退货率
回滚条件: 退货率高于大盘 5 个百分点，或 2 周内 0 成交
```

## 2. 状态机

```text
draft（草稿） → shadow（影子运行，只记录不执行）
             → active（正式生效，A 级）
             → deprecated（下线，保留历史）
```

- **draft**：只有假设，没有足够证据；
- **shadow**：按规则判断但不下发，对比"如果执行会怎样"；
- **active**：负责人确认，进入日常执行；
- **deprecated**：失效或引发问题，停止但留档。

任何状态变更都要记录人、时间、原因。

## 3. 置信度

| 级别 | 证据 | 建议 |
| --- | --- | --- |
| low | 1–2 例，或只有团队印象 | 只做观察，不写规则 |
| medium | 3–5 例，有反例但可解释 | 影子运行 2 周 |
| high | ≥ 10 例或 1 个强证据（客户明确说明原因），跨客群验证 | 可进入 active |

置信度不是永久标签。样本扩大后要重新评估。

## 4. 好规则与坏规则

| 规则 | 判断 | 原因 |
| --- | --- | --- |
| 客户问"勒不勒腰"→ 先发腰头特写再推荐 | 好 | 条件可观察，动作明确 |
| 客户犹豫 → 给限时折扣 | 坏 | 越权、不可持续、可能亏损 |
| 对老客要更热情 | 坏 | 无法执行、无法验证 |
| 48 小时未回 → 换由头追一次 | 好 | 时机明确，有停止条件 |
| 所有客户都发新品海报 | 坏 | 无分层，违反频控 |

## 5. 规则之间会冲突

| 冲突 | 优先级 |
| --- | --- |
| 营销规则 vs 不打扰 | 不打扰优先 |
| 成交规则 vs 授权边界 | 授权优先 |
| 新规则 vs 老规则 | 新规则先在影子运行，不直接替换 |
| 行业规则 vs 平台规则 | 平台规则优先 |

冲突无法解决时，升级给负责人裁决，不自行取舍。

## 6. 复盘节奏

- **每周**：看影子规则的数据，决定升 active 或退回；
- **每月**：清理 90 天未触发的规则（可能是条件写错了）；
- **每季**：重审高置信度规则，市场变了规则也会过期。

## 7. 写规则的人

规则由**最接近客户的人**提出（销售、客服），由**负责人**确认，由**技能**执行。
不要让没跟客户聊过的人凭空写规则，也不要让写规则的人自己批准上线。
