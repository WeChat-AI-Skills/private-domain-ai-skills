# 活动拉群与分层邀约

同一场活动，每个人收到的邀请应该不一样。
**先筛人，再分层；同意才进群；最后逐人核对。**

## 何时使用

- 要办试穿会、答疑会、限时活动、老客专场；
- 有客户池，但不知道邀请谁、怎么开口；
- 上次活动拉群后没人说话，或进群不下单；
- 活动结束要核对漏斗、列明日待办。

## 输入

活动目标、时间、地点/形式、权益与名额、客户池（对话/订单/标签）、上次活动数据（如有）。

权益、折扣、名额属于 B 级，必须先确认，不能由技能自行设定。

## 第一步：定义"谁该来"

先写清楚资格，再筛人。资格不是"所有老客"，而是能说清的一条：

```text
这场活动解决什么问题 → 谁有这个问题 → 用什么行为证明
```

示例：

| 活动 | 解决什么 | 谁该来 | 行为证据 |
| --- | --- | --- | --- |
| 周六试穿答疑 | 不确定尺码/版型 | 近 30 天问过尺码的人 | 对话关键词"码/身高/体重" |
| 老客专场 | 复购搭配 | 买过同品类的人 | 订单记录 |
| 新品首发 | 第一批尝试 | 高意向未下单 | 问过库存/价格 |

## 第二步：筛选与排除

```text
纳入：近 30 天问过相关品类 / 买过相关品类 / 高意向未下单
排除：不打扰名单 / 投诉未解决 / 已明确拒绝 / 30 天内已被邀约 2 次
观察：互动弱但标签匹配（不主动邀，可发朋友圈）
```

输出名单时给三类计数：**纳入 / 排除 / 观察**。排除要写原因，方便复核。

## 第三步：分层，一层一句

| 层 | 特征 | 邀约角度 |
| --- | --- | --- |
| A 问过尺码 | 近 30 天问过码 | "上次您问的版型，现场有真人试穿对比" |
| B 买过同品类 | 有订单 | "您买过的那条，这次有同版型新色" |
| C 高意向未下单 | 问过价格/库存 | "您上次看的那款，现场可以试" |
| D 观望 | 互动弱 | 不主动邀，只发朋友圈 |

一句话里必须包含：**为什么是你 + 你能得到什么 + 什么时候**。

```text
"您上次问的宽松版型，周六 14:00 群里有真人试穿对比，
想来我拉您进群？"
```

不写"亲爱的，我们有个活动"——那是群发，不是邀请。

## 第四步：征得同意

- 客户回复"想来/可以/好"才发群二维码或拉群；
- 未回复不二次追问，最多在活动前一天提醒一次；
- 客户说"不用"立即停止，记录原因；
- 不把客户直接拉进群再解释——那是硬拉。

## 第五步：群运营

群不是公告栏，要有节奏：

```text
活动前 1 天   群公告：时间、议程、需要准备什么
开场          自我介绍、规则、今天能解决什么
中段          按议程交付（试穿/讲解/答疑）
高潮          限时权益（需老板确认）
收尾          未答问题收集、下一步、预告
```

规则：

- 公告不超过 5 行；
- 每个问题都有人回，不回就是事故；
- 价格、折扣只在确认后说；
- 群内不刷屏，不连续发图；
- 活动结束 24 小时内解散或转为长期群，按事先约定。

## 第六步：漏斗核对

```text
已邀约 → 已同意 → 已进群 → 到场 → 下单
```

每一层给人数与转化率，标出最大流失点。不要只报"进群 80 人"这种虚荣数字。

## 第七步：明日待办

系统化列出，不靠记忆：

- 同意未进群 → 再发一次群链接；
- 进群未下单 → 3 天内按兴趣回访；
- 群内问尺码 → 转一对一（`customer-intake`）；
- 未回复 → 不进群，回朋友圈触达；
- 投诉/不满 → 转人工。

## 输出格式

```markdown
## 活动：周六试穿答疑（11-15 14:00）
目标：到店 15 人 / 群内成交 8 单

### 名单
纳入 42 · 排除 11 · 观察 23
（分层表格：A/B/C，人数，邀约句）

### 邀约
A 层（18 人）：…
B 层（14 人）：…
C 层（10 人）：…

### 群议程
10:00 公告 · 14:00 试穿 · 15:30 限时 · 17:30 收尾

### 待确认
- 限时权益力度
- 是否允许现场改码

### 风险
- 场地容纳上限 20 人
```

## 边界

- 不群发、不硬拉、不买群、不诱导分享；
- 不承诺未确认的权益与库存；
- 不把客户名单导出到公开渠道；
- 活动涉及医疗、金融等敏感主题时，先转合规确认。
