# 筛选与分层规则

## 1. 先写资格，再跑数据

```text
活动：周六试穿答疑
问题：不确定尺码，怕买错
证据：近 30 天对话里出现"码/身高/体重/尺码"
反例：只问过价格的人，不是这场活动的目标
```

资格写不清，筛出来的人一定不对。

## 2. 纳入规则

满足任一即可：

- 近 30 天问过相关品类或尺码；
- 买过相关品类（近 180 天）；
- 高意向未下单（问过库存/价格/活动）；
- 老客转介绍来的新客（需注明介绍人）。

## 3. 排除规则（优先于纳入）

| 排除项 | 原因 |
| --- | --- |
| 不打扰名单 | 明确拒绝/退订 |
| 投诉未解决 | 先处理问题，不邀活动 |
| 30 天内已邀约 2 次 | 频控 |
| 已明确说"不参加" | 尊重 |
| 未成年人/敏感行业限制 | 合规 |
| 无法确认身份的同名记录 | 防误发 |

排除要记录原因，不能悄悄丢掉。

## 4. 分层

| 层 | 规则 | 邀约句重点 | 预期同意率 |
| --- | --- | --- | --- |
| A 问过尺码 | 近 30 天有尺码问题 | 现场真人试穿对比 | 30–45% |
| B 买过同品类 | 有订单 | 同版型新色/搭配 | 20–35% |
| C 高意向未下单 | 问过价格/库存 | 现场试、当场答疑 | 15–30% |
| D 观察 | 标签匹配但无互动 | 不主动邀，只发内容 | — |

预期值只是估算，用自己历史数据替换。

## 5. 同意状态机

```text
待邀约 → 已邀约 → 已同意 → 已进群 → 已到场 → 已下单
            ↓          ↓
         未回应      同意未进群（待办：再发一次）
            ↓
         不参加（记录原因，不再邀）
```

每个状态都要有时间和操作人。状态不能跳级（没同意不能进群）。

## 6. 去重

- 同一微信多个备注：以有订单的为主；
- 同一人既在 A 层又在 B 层：归入更高意向层，只发一次；
- 夫妻/同事共用一个号：备注里写清，邀约时问"这次谁来"。

## 7. 名单质量检查

- [ ] 总数与分层数对得上；
- [ ] 排除项都有原因；
- [ ] 没有重复 ID；
- [ ] 每个人的邀约句能对应到具体依据（问过码/买过/问过价）；
- [ ] 不打扰名单零出现；
- [ ] 名单只在授权范围内流转。

## 8. 活动后回写

| 结果 | 回写 |
| --- | --- |
| 已同意未进群 | 待办 +1，24 小时内再发一次 |
| 进群未下单 | 标签 `行为:活动未购`，3 天内回访 |
| 到场未成交 | 记录原因（尺码/价格/犹豫） |
| 下单 | 标签 `行为:活动成交`，进入已购回访 |
| 投诉 | 转人工，活动相关标记风险 |

回写完成，这场活动才算结束。
