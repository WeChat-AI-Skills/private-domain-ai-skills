# 客户档案与分层

档案不是"把聊天记录抄一遍"，是**让下一个人接手时，三分钟内知道该做什么**。

## 何时使用

- 一次接待结束，需要把结果沉淀；
- 活动前要把客户池分层；
- 同事交接，需要补齐上下文；
- 同一客户在多个渠道出现，需要合并；
- 发现标签混乱、阶段判断不一致。

## 输入

对话原文、订单、历史档案、活动记录。至少要有客户标识（昵称或内部 ID）和一段可引用的原话。

没有原话时，只能生成"候选档案"，标注"未验证"。

## 档案卡结构

```yaml
id: c_1024
name: 小 A            # 昵称即可，不写真实姓名
source: 直播          # 直播 / 小红书 / 转介绍 / 线下 / 老客
stage: intent         # new / intent / purchased / repeat / dormant / do_not_disturb
需求:
  场合: 周末活动
  预算: 500
  偏好: [腰部宽松]
  品类: [裤装]
  尺码: M (165/55，待确认)
  城市: 杭州
标签:
  - 品类:裤装
  - 偏好:宽松腰
  - 行为:夜间咨询
  - 阶段:意向
互动:
  - at: 2026-11-12T23:48:00+08:00
    type: 咨询
    summary: 周末活动、预算500、腰部宽松
待办:
  - 确认收货城市与周六前时效
风险: []
```

字段缺失就留空或 `null`，不要用"未知"填满每一行——那会让档案看起来完整，实际上没有信息。

## 标签规范

统一格式：`维度:值`，中文值，不加空格。

| 维度 | 示例 | 用途 |
| --- | --- | --- |
| 来源 | `来源:直播` | 判断渠道质量 |
| 品类 | `品类:裤装` | 推荐与活动筛选 |
| 需求 | `需求:通勤` `需求:送礼` | 内容与话术 |
| 偏好 | `偏好:宽松腰` `偏好:纯棉` | 推荐精度 |
| 价格带 | `价格带:300-500` | 避免超预算推荐 |
| 阶段 | `阶段:意向` | 跟进节奏 |
| 行为 | `行为:夜间咨询` `行为:问过尺码` | 时机判断 |
| 风险 | `风险:投诉史` `风险:价格敏感` | 授权与话术 |

规则：

- 一个维度可以有多个值，但同一维度不要超过 3 个；
- 不造新维度；确需新增，先写进项目配置；
- 标签必须有依据（原话或订单），无依据的标"推断"；
- 定期清理 90 天未使用的标签。

## 分层规则

默认规则如下，负责人可按行业调整。**满足任一条件即进入该层，按从上到下优先匹配。**

| 分层 | 条件 | 跟进节奏 |
| --- | --- | --- |
| 不打扰 | 明确拒绝、退订、投诉未解决 | 不主动触达 |
| 高意向 | 近 7 天问过库存/尺码/价格，或明确说"要/怎么买" | 24 小时内 |
| 意向 | 近 30 天有互动，且需求四要素中至少 2 项明确 | 48 小时内 |
| 已购 | 有已完成的订单 | 7 天回访，30 天复购 |
| 复购 | ≥ 2 单，或近 90 天复购 | 专属权益，月度触达 |
| 沉睡 | 60 天无互动、无订单 | 月度唤醒，2 次无回应转不打扰 |
| 新客 | 刚加上，无互动 | 24 小时内破冰一次 |

分层不是永久标签。每次互动后重算，变化要写进 diff。

## 合并与冲突

同一客户多个渠道出现时：

1. 以有订单的 ID 为主；
2. 冲突字段以"更近的原话"为准，另一个值保留在备注；
3. 不合并只凭昵称相同的记录——同名太常见；
4. 合并前先给用户看"将合并的 2 条记录 + 冲突字段"，确认后执行。

## 输出格式

```markdown
## 档案更新：小 A（c_1024）

**变更**
+ 需求.场合: 周末活动（依据：11-12 原话）
+ 标签「偏好:宽松腰」
~ 阶段: new → intent（依据：问预算与版型）
+ 待办: 确认收货城市

**未变更**：尺码、城市（客户未答）

**下一步**：追问城市 → 核对时效 → 推荐 3 条
```

只写变化，不重抄整份档案。没有变化就说"无变更"。

## 隐私与边界

- 不记录身份证、银行卡、完整住址、健康史等敏感信息；
- 电话、地址如业务必需，只存脱敏值（如 `138****1234`），完整值留在业务系统；
- 档案用于当前服务，不用于训练通用模型；
- 客户要求删除时，转人工处理，不自行承诺"已删除"。
