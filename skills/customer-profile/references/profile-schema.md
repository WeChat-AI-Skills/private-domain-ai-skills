# 档案 schema 与分层计算

## 1. 完整 schema

```yaml
id: c_1024                  # 内部 ID，必填
name: 小 A                  # 昵称，不写真名
source: 直播
created_at: 2026-11-12T23:50:00+08:00
stage: intent               # 见第 3 节
owner: 店长王

需求:
  场合: 周末活动
  预算: 500
  偏好: [腰部宽松]
  品类: [裤装]
  尺码: null
  城市: 杭州

标签:
  - 品类:裤装
  - 偏好:宽松腰
  - 行为:夜间咨询
  - 阶段:意向

互动:
  - at: 2026-11-12T23:48:00+08:00
    type: 咨询            # 咨询/跟进/下单/售后/活动
    channel: 微信
    summary: 周末活动、预算500、腰部宽松
    evidence: "周末有个活动，预算 500 左右，想要一条腰部宽松点的裤子"

订单:
  - id: o_88
    at: 2026-10-01
    amount: 359
    sku: 直筒黑M
    status: 已完成

待办:
  - 确认收货城市与周六前时效
  - 推荐 3 条腰部宽松款

风险: []
备注: null
```

## 2. 字段规则

- `id` 一旦生成不改；跨渠道合并时保留主 ID，另一个进 `merged_from`；
- 时间一律 ISO 8601，带时区；
- 金额带币种（默认 CNY）；
- `evidence` 存原话，不存转述；
- 未知用 `null`，不要写"未知""待补充"这种字符串；
- 数组为空就 `[]`，不要留空字符串。

## 3. 阶段计算

按顺序判断，命中即停：

```text
1. 明确拒绝/退订/投诉未解决        → do_not_disturb
2. 近 7 天有购买信号（问库存/尺码/价格，或说"要"） → high_intent
3. 有已完成订单
   3a. ≥2 单 或 近 90 天复购        → repeat
   3b. 否则                         → purchased
4. 近 30 天有互动，需求 ≥2 项明确   → intent
5. 60 天无互动且无订单              → dormant
6. 其他                            → new
```

"购买信号"要引用原话，不能凭感觉。判断不了就留在 `intent`，不要升级。

## 4. 分层与动作

| stage | 触达窗口 | 默认动作 | 授权 |
| --- | --- | --- | --- |
| high_intent | 24h | 给方案 + 一个追问 | A（草稿）/ B（发送） |
| intent | 48h | 给证据 + 轻推进 | A |
| purchased | 7 天回访 | 使用回访、搭配推荐 | A |
| repeat | 30 天 | 专属权益、优先购 | B（涉及权益） |
| dormant | 30 天一次 | 唤醒内容，2 次无回应停 | B |
| do_not_disturb | 不触达 | 只做服务性回复 | C |

## 5. 变更 diff

输出只写变化：

```diff
+ 需求.城市: 杭州
+ 标签「行为:问过尺码」
~ stage: new → intent
+ 待办: 推荐 3 条腰部宽松款
- 待办: 确认收货城市（已完成）
```

diff 要能直接合并进系统；不能合并的字段（如自由备注）单独列出。

## 6. 质量检查

一份合格档案应满足：

- [ ] 至少 1 条带原话的互动记录；
- [ ] 阶段有依据（标签或原话）；
- [ ] 待办是"动词 + 对象"，不是"关注一下"；
- [ ] 没有敏感信息；
- [ ] 标签符合命名规范，同维度 ≤ 3 个；
- [ ] 风险字段如实填写（没有就空数组）。

## 7. 合并记录

```yaml
merged_from:
  - id: c_205
    at: 2026-11-12
    reason: 同一微信，旧 ID 无订单
    conflicts:
      - field: 需求.城市
        kept: 杭州
        dropped: 上海（旧记录，未确认）
```

合并必须留痕，方便回滚。
