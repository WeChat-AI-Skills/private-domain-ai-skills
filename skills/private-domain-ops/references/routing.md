# 路由细节与分诊示例

## 1. 分诊的四个问题

拿到一句话请求，先在心里回答：

1. **对象是谁？** 一个客户、一批客户、还是一群陌生人（活动）；
2. **现在在哪一步？** 刚接触、已识别、已购、沉睡、出问题；
3. **要产出什么？** 一条回复、一份名单、一个排期、一张规则卡、一个决定；
4. **谁执行？** 技能出草稿、系统发送、还是人工接手。

答完这四个问题，技能自然就定了。

## 2. 容易混淆的边界

| 看起来像 | 其实应该 | 原因 |
| --- | --- | --- |
| "帮我写条催付" | `followup-plan` | 先判断该不该催、什么时候催，再写 |
| "这个客户怎么回" | `customer-intake` | 回复只是结果，先拆需求 |
| "把这批人拉个群" | `campaign-invite` | 先筛人分层，再谈拉群 |
| "朋友圈文案" | `moments-calendar` | 单条文案也要放进一周节奏里看 |
| "最近转化怎么掉了" | `sales-review` | 先看数据与对话，再改规则 |
| "把这段话发出去" | 授权复核 | 不生成新内容，只核对与执行 |

## 3. 示例一：一句话里有三件事

> "昨晚有几个客户问裤子，你帮我回一下，顺便看看这周朋友圈发什么。"

拆成三个任务，按优先级排队：

1. 逐个 `customer-intake`（高意向，先做）；
2. 聊完的进 `customer-profile`（沉淀）；
3. `moments-calendar` 排本周内容（可以下午做）。

不要在一个回合里同时做完三件事——先交付第一批回复，再做排期。

## 4. 示例二：授权不清

> "把这条活动发给所有老客。"

先问三个问题：老客的定义是什么？发多少人？谁确认过权益？

- 没有名单 → 先 `campaign-invite` 筛选；
- 没有确认 → B 级，先出"将发送的原文 + 名单 + 时间"；
- 数量大 → 建议分批（每批 ≤ 50），先发 5 人试水。

## 5. 示例三：该停的时候

> "客户说要投诉，你先帮我回一段。"

C 级。不要写"安抚话术"去拖，直接出交接卡，附客户原话与已确认事实，交给能处理的人。技能可以帮写"我们已收到，专人 2 小时内联系您"这种不承诺结果的过渡句，但不能代替处理。

## 6. 一次只进一个技能

总控的职责是**选路**，不是把所有技能都跑一遍。判断链：

```text
有明确客户 + 有对话  → customer-intake
有档案 + 要决定时机  → followup-plan
有一批人 + 有活动    → campaign-invite
有目标 + 要内容      → moments-calendar
有结果 + 要改规则    → sales-review
以上都不是           → 先问清楚目标
```
