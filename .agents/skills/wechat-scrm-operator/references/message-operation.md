# 指定好友的任务式消息

先按[工具与会话检查](tool-and-session-check.md)定位当前会话，沿用[好友消息技能](../../wechat-scrm-friend-message/SKILL.md)。已排期任务的修改以[提交回执第 5 条](../../wechat-scrm-onboarding/references/operation-receipts.md#scheduled-task-changes)为统一规则，直接看下文第 5 节；不要重走新建任务步骤。聚合聊天即时回复另行适配，不能用另一发送入口替代未定位的任务表单。

## 1. 明确对象与入口

核对原工作号、稳定好友标识、当前好友关系、拒联和人工接管状态，以及已批准的频次、额度和时间窗口。昵称相同、分群归属变化或联系人映射不明时，不发送给“看起来像”的对象。现有有效授权继续复用。

当前菜单可能为“定时消息 → 好友消息”，或“微信管理 → 群发配置 → 好友消息”。核对页面确有任务列表、好友消息页签、账号/标签或通讯录选择、开始时间、间隔和消息编辑区。

不要将“群消息”“公司标签消息”误选为指定好友任务，也不要把“自动化任务”的长期欢迎消息开关当作本次单条发送。

## 2. 选择账号和联系人

1. 在账号区域按稳定工作号选择；清除与当前任务无关的残留选择，回读账号状态。
2. 进入通讯录或本次指定分群。标签只是筛选条件，读取当前实际名单再判断范围；不能把同名标签或历史人数当成当前选中对象。
3. 单人任务回读“已选 1 个好友”，同时核对这个人的稳定标识及所属工作号。名单任务核对实际对象列表、勾选数、去重和排除项。
4. 查询原账号的已有任务/触达记录，避免同一目标重复发送。不存在统一“隔 24 小时就能重发”的默认规则，按客户已批准策略执行。

## 3. 时间与消息块

| 字段 | 操作与回读 |
| --- | --- |
| 开始时间 | 设置绝对日期时间并核对业务时区；控件失焦后读取实际保存值 |
| 时间区间 | 当前执行窗口必须覆盖开始时间；可能次日续跑时核对任务有效期和停止条件 |
| 间隔时间/好友发送间隔 | 使用批准频控及账号/企业额度；不把截图或页面默认秒数当政策 |
| 内容类型 | 第一轮优先文字/图片；小程序等按当前企业实际选择器及素材支持单独核验 |
| 新增多选消息（同一条） | 核对是否随机择一或组合方式，不能靠名称猜测。任务要求固定顺序时不要选不明的多选模式 |
| 新增多条消息（另一条）/发送多条 | 固定顺序内容使用独立消息块，逐块核对顺序、文字换行、上传完成与预览 |
| 昵称变量 | 例如页面提供的备注替换变量，只有任务允许且身份映射准确时使用；检查最终含义，不把未展开变量当已核对正文 |
| 发送后撤回等开关 | 仅按明确任务/批准默认值设置；不得因为页面提供就自动启用 |

小程序/公众号/视频号卡片应核对真实身份、标题、封面和来源，缺实际选择器或字段说明时交付缺口，不用文本链接冒充原生卡片支持。

## 4. 提交一次并回读原任务

再次核对当前租户、工作号、联系人、最终内容与顺序、时间区间、间隔和适用开关。授权齐全且仍有效时提交一次。

从同业务“任务列表”找到原任务，保存任务 ID；没有 ID 则用账号、对象、创建/计划时间和内容唯一定位。重开“查看内容”核对实际配置，记录状态及进度。

如果只有“使用任务配置”能展开内容，先确认打开它不会自动保存或新建任务，再用它只读核对；回到原任务，**不再次提交复制表单**。若打开本身有副作用或无法判断，使用详情/原会话等证据或报告内容待核。

查原工作号中本次目标的出站记录、内容、时间及结果。任务受理、出站成功、客户已收/已读/回复是不同阶段；缺后者证据时保持未核实。出现部分成功时逐对象列出，不用总“已执行”替代明细。

提交超时、会话断开、状态矛盾或客户要求暂停时，依[原任务与状态核对](readback-and-recovery.md)处理。持续回访/自动欢迎规则不属于本次单任务授权，不默认启用。

## 5. 已排期任务修改

确认原任务尚未执行，用原任务 ID 打开「修改」。仅改文案、图片、链接或小程序卡片时，原地保存后重开同一 ID，逐块核对新内容、消息顺序和排版，确认发送账号、稳定收件人名单、发送时间与原安排一致。当前部署是否支持相应素材另行核对。

找不到「修改」、修改失败或保存后读回不一致时停在原任务，报告 ID 与具体问题；保存结果不明确时先查询原任务，不再次提交。禁止通过取消重建、复制配置后重新提交或重发完成内容修改。「使用任务配置」仅用于核对已保存内容与勾选项。

仅整批更换收件人名单或发送账号且已核实原任务无法修改时，向企业指定负责人报告原任务、更换范围和无法修改的证据，等待明确决定，保留原任务。获准取消并重建后，先回查旧任务确已取消且未执行，再建替代任务并关联原 ID；仅获准取消而未获准重建、取消未确认或执行状态不明时不能新建。
