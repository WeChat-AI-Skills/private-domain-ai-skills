# 工具与会话检查

目标是确认当前 Codex 能读到客户指定的 SCRM 会话，并知道本次操作的实际入口。已有检查记录可复用；账号、页面、工具或权限变化时刷新相关项。不要为了“完整上岗”读取与本次任务无关的全部聊天、联系人或财务资料。

## 1. 找到实际操作工具

从宿主暴露的工具列表和已安装技能中寻找客户可用的浏览器/桌面控制入口，先读取其说明。至少确认：

| 所需能力 | 实际检查 |
| --- | --- |
| 选中客户会话 | 能选择正确浏览器标签页或原生窗口，并读取其当前地址/页面身份 |
| 读取界面 | 能读取页面文本/结构或清晰截图，辨认当前工作号和表单标签 |
| 操作控件 | 当前工具支持点击、输入、下拉与日期控件；只读上岗只检查工具说明，不试提交 |
| 上传素材 | 图文任务需有正式文件选择/上传方式；不能把本机路径字符串当上传已完成 |
| 查询结果 | 可返回任务列表、打开原任务详情或获授权的原会话 |

记录真实工具名、版本或可用版本信息、所选会话引用。网页 GET、文件下载成功或本机浏览器已安装，不能替代对这个已登录会话的实际读取。

没有控制工具时，明确报告“技能已安装，当前宿主缺少能操作指定 SCRM 会话的工具”。优先使用客户已配置、宿主正式支持的连接方式；安装或启用新的服务按客户选择和宿主说明处理。不得自动修改全局浏览器配置、导出会话凭据或改用未说明的远程控制软件。仍可先准备业务草稿和必要字段清单。

## 2. 连接客户指定入口

复用[客户环境卡](../../wechat-scrm-onboarding/references/customer-setup.md)中已有入口。没有入口时只补实际 URL 或客户指定窗口；不内置维护者的地址。

1. 选中客户指定的标签页/窗口，核对实际站点与入口。登录页或跳转到其他域时确认仍属于客户正式系统。
2. 缺登录、验证码或二次验证时，由客户在正式界面完成。登录结束后重新读取页面，不能根据客户说“登录了”就假定选中会话正确。
3. 读取页面上的企业/租户、当前角色和授权工作号。工作号用稳定账号标识；昵称只作为辅助。核对业务时区，页面只给本地时间时确认如何转换。
4. 查看授权工作号在线/离线/异常状态。能看见一个账号不代表有发送权限；只有本次任务所需的账号才进入后续范围。
5. 将客户本地绑定保存在受控工作区。会话引用只作定位，不保存 Cookie、密码、验证码或完整认证配置。

如果不同浏览器隔离了登录态，报告“客户已在另一个会话登录，当前工具尚未连接该会话”，不要冒用其他账户或复制 Cookie。

## 3. 只读定位本次入口

从当前侧栏、页签和实际页面标题定位，名称可能因部署而不同：

| 本次操作 | 菜单线索 | 只读检查结果 |
| --- | --- | --- |
| 图文朋友圈 | 朋友圈管理 → 朋友圈任务 / 发圈管理 → 发表朋友圈 | 当前标题、图文类型、工作号选择、时间、可见范围、任务列表与详情入口 |
| 好友任务消息 | 定时消息 → 好友消息；或微信管理 → 群发配置 → 好友消息 | 当前标题、通讯录/标签、账号、选中人数、时间窗口、任务列表与内容查看入口 |
| 原任务查询 | 同业务的任务列表/详情；必要时原账号出站会话 | 可以用什么稳定任务标识定位，是否能看到逐账号/对象结果与时间 |

“每日任务”“自动化任务”“定时消息”不是同一页面。不能因为出现“已执行”就把任一列表当作本次消息/朋友圈的结果。无唯一入口时记录当前页面和缺口，不凭旧坐标盲点。

只读检查不要填写可能自动保存的字段、试发消息、点击发布、切换自动通过/回访开关、导出全量资料或启动远程协助。必要字段和默认值的实际读回在对应已获授权的操作中完成。

## 4. 上岗回执

按下列层级分别给出结论，缺项使用“未确认”，不要统称“连接成功”：

- 技能：版本和宿主识别情况。
- 工具：能否实际读取指定会话；工具/会话引用及核对时间。
- 身份：企业/租户、角色、工作号和时区是否匹配。
- 入口：本次操作的页面与结果入口已定位/无权限/未定位。
- 执行：本操作未测试/已提交/结果已核对；授权范围和仍缺条件。

只读上岗不证明写入已通过。后续每次提交前再次确认当前账号和最终内容，复用有效业务授权；仅对发生变化或确实缺失的范围向客户补问。
