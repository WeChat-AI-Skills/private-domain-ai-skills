# 图文朋友圈：填表、排期、修改与回读

先按[工具与会话检查](tool-and-session-check.md)确认当前会话，沿用[朋友圈技能](../../wechat-scrm-moments/SKILL.md)和[提交回执规则](../../wechat-scrm-onboarding/references/operation-receipts.md)。本路径优先处理图文。视频、链接、视频号、位置、自评等字段有页面线索，但必须在客户当前版本分别验证。

## 1. 准备与查重

固定本次工作号、最终正文、图片原件及顺序、绝对发布时间和业务时区、可见类型与对象。采用客户本条要求或已批准默认值；位置、水印、评论和随机替换不能沿用不明的页面残留。

按商品/活动资料核对对外事实。工作号离线、素材缺失、时间过期、可见对象身份不清、已有排期冲突等先处理；只影响某个账号时保留其他账号的独立状态。

在朋友圈任务列表查询同工作号、相邻计划时间及内容，确认是否已有同一目标任务。相同文案不必然是重复任务，必须结合对象、时间和用户意图；已有同一任务时读取或按授权修改原任务。

## 2. 进入表单并逐项核对

从“朋友圈管理”查找“朋友圈任务”或“发圈管理”，再选“发表朋友圈”。核对当前标题、账号选择区域、内容类型和任务列表页签。以下标签是线索，实际控件必须从当前页面观察：

| 字段 | 页面操作与必须回读的值 |
| --- | --- |
| 工作号 | 按部门/小组/工作号过滤，用稳定标识核对勾选对象；先清除与任务无关的残留选择。单号任务确认仅一个账号 |
| 内容类型 | 选择“图文”，确认没有停留在视频/分享链接/视频号或素材库的其他类型 |
| 图片 | 用工具正式上传原件，等待每张上传完成。逐张对照缩略图、数量与顺序；缺图、重复图或仍在上传时不提交 |
| 正文 | 按最终标点和换行录入；回读完整正文。若页面含随机字符/多样化设置，确认本任务是否允许，默认不引入随机改写 |
| 发送时间 | 打开时间控件，设置明确日期与时间；失焦或关闭控件后读取实际值。界面的“现在”不是未来排期，时区不同需先转换并复核 |
| 谁可以看 | 选择公开/私密/部分可见/部分不可见中本任务明确要求且当前实际支持的一项。需要名单时核对稳定对象和实际勾选数，不能只看标签名称 |
| 所在位置 | 只有任务要求或批准默认值才设置。回读具体位置，不把展示位置当账号真实地理位置证据 |
| 水印等开关 | 逐项核对本条要求或批准默认值，不因页面默认勾选就继承授权 |
| 添加评论/延迟 | 本系统“定时自评”指发圈账号的后续评论。核对评论正文、延迟单位和时间；它与主帖子分别有执行结果 |

表单若有自动保存，填写即属于写入。只读或仅草稿请求应在客户工作区准备内容，不以“尚未点发布”为由把填写归为只读。

## 3. 提交与保存核对

提交前以当前页面重新核对租户、工作号、最终图文、时间、可见范围及附带动作。有效授权已覆盖这些项时继续执行；只有范围/内容发生变化或缺授权时补齐，不机械重复确认。

提交一次，保存平台给出的任务 ID 和可见状态。随后回到同业务“任务列表”，用原 ID 打开原任务。没有 ID 时用工作号、创建时间、计划时间及完整内容共同定位，必须唯一。

重开详情逐项比较：工作号、正文换行、图片数量顺序、计划日期时间、可见范围、位置/水印/评论等适用开关。字段不一致时停在原任务，报告任务 ID 与具体差异；保存结果不明时先查原任务。不要新增一条任务掩盖保存错误。

只确认保存和待执行时报告“排期已保存”，保留查询时点。提交超时、无结果或出现多个相似记录时，按[原任务恢复](readback-and-recovery.md)先查证，禁止直接再次提交。

## 4. 修改与到期核对

修改统一执行[提交回执第 5 条](../../wechat-scrm-onboarding/references/operation-receipts.md#scheduled-task-changes)。先读原任务状态；已执行、执行中或状态未知时，先核对并报告，不套用尚未执行任务的内容修改流程。

已排期且尚未执行、只更改文案/图片/链接/小程序卡片时，用原 ID 打开「修改」，只改获准内容并原地保存。保存后重开同一 ID，核对新内容、正文换行、图片顺序及排版，确认发送账号、可见范围和时间与原安排一致，记录修改前后版本。各素材类型仍须由当前部署实际支持，不能把本规则当作已支持全部媒体的证明。

找不到「修改」、修改失败或读回不一致时，停在原任务并报告 ID 和具体问题；保存不明确先查原任务。禁止取消重建、复制配置重新提交或重发来代替内容修改。「使用任务配置」只核对已保存内容与勾选项。

仅收件人名单或发送账号需整体更换，且有证据证明原任务无法修改时，才按第 5 条报告企业指定负责人，等明确决定并保留原任务。如获准取消并重建，先读回旧任务确已取消且未执行，再创建关联原任务 ID 的替代任务。没有该证据时不建替代任务。

到期查询原任务逐工作号结果及实际执行/上报时间。平台“已执行”或总进度只有在明确证明该账号这条内容已发布时才能映射为发布完成。观察账号获授权且在验收范围内时，另查对应内容和可见范围；平台发布记录不能自动证明所有客户可见。延迟评论另查正确帖子、评论内容、账号和时间。

首个现场演练可选会话能够覆盖的近时排期。长时任务由 SCRM 执行；无宿主调度能力时保留待查任务和续查指令，不承诺 Codex 关闭后的自动回读。
