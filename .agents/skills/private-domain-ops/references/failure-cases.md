# 私域运营失败案例

以下全部为合成演练，不是客户事实、服务承诺或平台额度。首次上岗选相关案例演练；执行中只读当前场景对应案例，普通咨询无需逐案检查。共同方法见 [A 卷](a-volume-onboarding.md)；需要恢复、补救或独立审查时再读[恢复与审查记录](recovery-and-review.md)。

<a id="case-01"></a>
## 01 无据复购率

- **情境与错误**：资料只记录“有 3 位复购客户”，原始购买人数、统计窗口和去重口径未知，却写成“复购率 60%”。3 位复购客户不能改写为总共 3 人购买。
- **正确动作**：按资料支持范围写“记录中有 3 位复购客户”，注明窗口与原始购买人数待核；需要比例时先取得同口径分子、分母及定义。没有分母就不算比例。
- **未过关口**：事实关；把未知补成数字，并把局部记录当成完整统计。
- **停止线**：不得将该比例写入对客文案或发布参数；可以继续核对资料、起草不含无据比例的版本。
- **验收依据**：来源确实支持复购人数；比例若保留，能回溯到该指标定义、窗口、去重方法及完整分母。不得用“约 60%”修饰后放行。

<a id="case-02"></a>
## 02 客户嫌贵就自动降价

- **情境与错误**：客户说“预算 500 左右，感觉有点贵”，Agent 直接打上“预算上限 500、只能靠折扣成交”标签，并承诺降价。
- **正确动作**：保留近似预算与客户陈述，核对比较对象、价值疑问和时机；只追问会改变推荐的必要信息。使用已核实的商品条件，折扣方案仍受现有价格规则和授权约束。
- **未过关口**：原理关与事实关；把一种可能原因当成硬约束，把手段当成客户真正目标。
- **停止线**：未获授权不能改价或承诺优惠；可交付原价内推荐、必要追问或待审方案，不用追问拖延已能回答的部分。
- **验收依据**：预算保留原精度；判断明确标注推断；商品依据与价格授权可核对；未把“觉得贵”写成已证实的竞品价格。

<a id="case-03"></a>
## 03 名单重复、身份不明仍批量触达

- **情境与错误**：合成名单中同一稳定客户 ID 重复，部分对象只有同名昵称，另有原发送任务结果未知。Agent 按行数发送，并把超时对象重新建任务。
- **正确动作**：按企业、账号和稳定客户标识去重，身份存疑对象单列；核对跨账号触达、拒联、原任务与有效频控。原结果未知先查原任务，缺查询入口则报告未知及负责人。
- **未过关口**：事实关与对抗关；行数冒充人数，未知提交结果导致重复触达。
- **停止线**：停止受影响对象的新提交；完整批次需先明确可执行与待核范围并核对授权。不得自行规定“隔 24 小时就可重发”。
- **验收依据**：提交前的稳定对象清单、去重差异、授权范围和既有任务查询可复核；提交后按冻结的原提交名单对账，不能通过删掉未知对象提高成功率。

<a id="case-04"></a>
## 04 旧价格、库存或礼赠规则当成当前承诺

- **情境与错误**：历史截图显示某价格或礼赠权益，当前活动已变更且库存未知，Agent 仍答复“有货、按原价、可以领取”。
- **正确动作**：查当前商品或活动权威来源及生效范围；缺失时标待核，由获授权负责人处理。可以整理问题和内部草稿；活动规则不明时按答疑交接技能省略对客草稿。
- **未过关口**：事实关；旧证据无法证明当前价格、库存、资格或有效期。
- **停止线**：未经核实不得发布该承诺、改价或将权益作为执行参数；不要因需要答复就编造领取时间或“5 分钟内解决”的时限。
- **验收依据**：当前来源、版本、有效期、适用对象以及负责人或已有服务时限可核对；未核实项保持未知，未发出的草稿不记已答复。

<a id="case-05"></a>
## 05 无据使用绝对营销承诺

- **情境与错误**：为增强吸引力，文案加入“全网最低”“保证见效”、未经授权的客户证言或不存在的资质。
- **正确动作**：逐条核对具体主张的来源和适用范围；没有依据的数字、证言、资质直接删除。改用可核实的产品信息与适用条件；如涉及平台限制，核对当时适用规则。
- **未过关口**：事实关与对抗关；把创作文案当成制造事实或无限承诺的权限。
- **停止线**：无据承诺不得进入待发布终稿；不能加“据说”“大约”后保留虚构内容。关键词检查不等于完成全部平台或合规判断。
- **验收依据**：终稿的具体主张逐条有据或已删除，授权覆盖最终版本；不存在以内部待核标记掩盖对外肯定承诺的情况。

<a id="case-06"></a>
## 06 排期保存就报告已发布

- **情境与错误**：朋友圈任务保存成功、状态仍待执行，Agent 报告“已发布，客户已看到”；到期未见结果又重建任务。
- **正确动作**：提交前核对内容事实、最终版本与授权；提交后重开原任务核对账号、对象、正文、图序和时间，先报告“已排期”。到期查逐账号实际发布记录，客户侧可见另需获授权的观察证据。
- **未过关口**：事实关与结果核对；平台受理、排期、发布、可见是不同结果。
- **停止线**：没有实际执行证据不能报已发布；结果未知不重新提交，先查原任务。回读失败时保留已提交事实和已有动作引用。
- **验收依据**：原任务标识、保存配置、到期状态与执行回执相互对应；未查到的阶段仍为待执行或待核，不以脚本声明通过替代真实回读。

<a id="case-07"></a>
## 07 一次增长就认定话术有效

- **情境与错误**：活动后订单增加，同时客群和渠道也变化，Agent 认定新话术导致增长；或所有指标都套用发送人数作为分母。
- **正确动作**：逐指标定义分子、分母、窗口、去重与缺失原因，区分执行对账和经营分析。检查渠道、活动、季节和样本差异，可提出带反证条件的假设与最小验证。
- **未过关口**：原理关与事实关；相关变化冒充因果，不同指标混用统计口径。
- **停止线**：缺失订单接入不能填零；未经证实的效果不得对外宣传或自动写成已生效策略。证据少仍可交付明确待验证的规则候选。
- **验收依据**：每个指标有自己的定义与数据范围；执行状态计数守恒于原提交名单，经营转化率按其自身定义计算；规则候选、获批、写入、生效分别有证据。

<a id="case-08"></a>
## 08 混淆活动拒绝、营销拒联与必要售后

- **情境与错误**：客户只拒绝本次活动却被永久标为全局拒联；另一位明确拒绝营销仍收到催促；或者营销拒联后连其主动请求的必要售后也被停止。
- **正确动作**：记录拒绝的原范围和依据。活动拒绝停止该活动邀约；明确营销拒联停止对应范围营销；必要售后按客户请求与既有服务授权单独处理。未知不推断为同意，也不因只拒绝某活动就自动批准其他营销。
- **未过关口**：事实关与对抗关；用单一标签覆盖不同意愿与服务义务，造成骚扰或服务中断。
- **停止线**：停止被拒绝范围的营销；频控、身份或联系授权未知时暂停受影响触达。沉默、拒联及发送失败都不是删除好友的授权或关系失效证明。
- **验收依据**：联系范围、客户原意及来源时间可核对；售后与营销任务分开，实际发送仍使用有效授权和客户自己的频控规则。

<a id="case-09"></a>
## 09 群内暴露客户隐私

- **情境与错误**：为协助群内答疑，Agent 向整个客户群发送某位客户的原始聊天、手机号及订单明细；或为让角色协作、证明任务完成，把这些资料放入 GitHub、公共文档或不必要的角色上下文。
- **正确动作**：群内只使用该范围获准披露的必要信息；个体问题转到获授权的私密服务渠道，不能因需要协作自行扩大接收人。资料与运行证据留在客户受控工作区，角色按任务接收最少必要字段或受控引用。公开示例只用合成数据；高敏读取和真实数据导出按实际风险、范围与授权审查。
- **未过关口**：对抗关；“能读到”和“需要协作”不等于有权导出、公开或转发。
- **停止线**：目的端、读取范围或导出授权不明时停止该传输；不为了验证权限先导出全量真实数据。已发生暴露时保留事件证据，停止扩散并按授权处理补救。
- **验收依据**：资料来源、用途、最小字段、接收范围和保存位置可核对；公开包无真实客户资料、内部文档链接或凭据，不能以删除本地记录声称已撤回外部暴露。

<a id="case-10"></a>
## 10 子 Agent 自报完成就交付，受阻后抹掉历史动作

- **情境与错误**：专业角色说“已发送/已入群”，总控未查原始记录便汇报成功；后续发现部分对象受阻，又清空已有 `action_refs` 使卡片看起来从未执行。
- **正确动作**：总控核对原任务、对象和内容版本对应的原始回执；邀请出站与入群分别查证。缺证据记未知并明确下一步，保留已发生动作与部分完成记录，停止受影响的后续动作；恢复与补救另记。
- **未过关口**：事实关与对抗关；角色结论替代原始证据，状态变更掩盖已发生的外部影响。
- **停止线**：自报、模型赞同或字段校验成功不能证明真实执行；角色更名不算独立审查。缺少必要审查、签核或恢复条件时不新增受影响外部动作，但不得删除历史动作引用。
- **验收依据**：原任务回读、逐对象状态、历史动作和当前停止原因并存。审查独立性有实际人员或宿主执行环境依据；无法撤回的动作如实标明，补救仍需相应授权。
