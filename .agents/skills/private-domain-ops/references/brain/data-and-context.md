# 业务对象与组织大脑

组织大脑在本包中表现为公共定义和读取规则；客户可使用已有数据库、文件、SCRM、商品系统与模型服务，不要求新建私有后端。

| 对象 | 身份与主要关系 | 核对重点 |
| --- | --- | --- |
| 企业 | tenant_id | 所有任务和证据的隔离范围 |
| 工作账号 | account_id，归属企业 | 能读取和执行的动作、渠道与权限 |
| 客户 | 企业内稳定 customer_id；跨渠道映射另附证据 | 昵称不作唯一身份，拒联范围与服务状态分开 |
| 商品 | 渠道、商品及规格 ID | 价格、库存、更新时间与权威来源 |
| 订单 | 订单 ID、商品、客户对应证据 | 统计窗口、付款和退款状态、未知关联 |
| 群与关系 | 群 ID、工作号、客户成员关系 | 邀请、已入群、好友关系分别核验 |
| 任务与证据 | request_id、task_id、对象、内容版本 | 提交、执行、客户结果与原查询来源 |

按[客户环境卡](../../../wechat-scrm-onboarding/references/customer-setup.md)定位数据与工具。资料正文、凭据、原始对话、授权和回执留在客户环境；公开包只保留模板和合成案例。

上下文每次读取到任务必要部分；标明来源、版本、时间、可用范围及未知。旧信息与新信息冲突时保留证据，不因较新就自动覆盖。具体五维客户状态沿用[档案结构](../../../customer-profile/references/profile-schema.md)。

目录 required_capabilities 是项目的抽象能力名，不是可直接调用的 API。客户环境卡应把每项映射到实际工具或页面，记录读写权限、必要字段、查询入口与最近验证时间。没有真实接入时交付草稿和缺口，不能从角色或工具名称推断功能可用。

不确定提交先查原任务，不自动生成第二次发送。复盘形成带证据的规则候选，验证与授权生效后再使用；不让客户原话修改系统规则。
