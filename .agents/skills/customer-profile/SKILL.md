# 客户档案与分层

输入：企业与账号范围、稳定客户 ID 或待匹配引用、获授权的记录、已有档案与标签规则。

1. 先核实身份。只有昵称时可以建立待匹配草稿，不合并、不写入正式客户记录。跨渠道合并需可信的身份对应证据。
2. 按[档案结构](references/profile-schema.md)记录事实、推断、待确认、来源、更新时间和负责人。近似预算保留原话及精度，金额注明币种。未知保留 null；只有确认没有时才填空数组。
3. 使用客户自己的标签字典。标签记录可观察行为或明确需求，避免“易怒”“好说话”等无依据的人格判断。参考[标签体系](references/tag-system.md)。
4. 关系阶段、购买历史和营销许可分别记录。重复购买先于单次已购判断；身份或历史不足时保留待核。拒联优先于营销分层，服务问题单独处理。
5. 输出增删改 diff 及每项依据。冲突记录并存并标时间，不能仅因新记录较近就覆盖来源更可靠的事实。
6. 实际写入、合并或标签删除必须有相应授权与已适配入口，按[授权规则](../private-domain-ops/references/authorization.md)处理。写后回读字段；无入口时保留可导入草稿。

输出：客户引用、变更 diff、依据、未解决冲突、写入状态、下一步。完整客户资料留在客户批准的业务环境。
