# SCRM 上岗检查

接令时按[A卷上岗原则](../private-domain-ops/references/a-volume-onboarding.md)核对事实、真实问题与失败路径；按风险调整留证，同一任务复用已完成判断与有效授权。

开始前读取[客户环境卡](references/customer-setup.md)，复用已提供的信息。安装技能后仍需核实客户自己的 SCRM 入口、账号和工具。多业务任务可交给[私域运营总控](../private-domain-ops/SKILL.md)。

1. 使用企业正式入口和已授权会话，核对企业名称、当前角色及业务时区。需要登录时由操作者在官方界面完成。
2. 核对授权工作号的稳定标识、归属、用途和状态（可用、离线、异常、禁用）。盘点允许触达的时段、账号额度、企业总额度、批次上限及现有排期。
3. 核对客户名单或分群来源、稳定客户标识、归属账号和拒联规则。确认群类型、目标群标识、容量、可邀请人和成员核验入口。落实最终内容、素材及关系清理的负责人。
4. 检查以下入口在当前后台的实际名称及权限。菜单存在只表明入口可见。

| 业务 | 待在当前系统核对的定位线索 |
| --- | --- |
| 朋友圈图文 | 朋友圈管理 → 发圈管理 → 发表朋友圈 |
| 好友消息 | 微信管理 → 群发配置 → 好友消息 |
| 现有群邀请 | 聊天 → 进入目标群 → 群成员 → 添加 |
| 好友删除排期 | 微信好友 → 删除任务 → 删除好友 |

汇报企业、角色、授权账号和四项入口的「可见」「无权限」或「未定位」，同时列出缺失配置。首次检查保持只读。表单演练使用企业指定的测试工作号、测试联系人和测试群，提交以当次任务授权为准。

后续动作使用[提交与回执](references/operation-receipts.md)。
