# 任务结果核对

接令时按[A卷上岗原则](../private-domain-ops/references/a-volume-onboarding.md)核对事实、真实问题与失败路径；按风险调整留证，同一任务复用已完成判断与有效授权。

输入：企业、账号、原任务 ID 或幂等标识、原始目标名单、动作、内容版本、已获授权的查询入口和已有回执。名单及证据留在客户工作区。

1. 找到原任务，核实企业、账号、动作与内容版本一致。提交超时表示结果未知，先查原任务/原幂等标识；不创建新任务来试探结果。没有查询入口时交付待核对项。
2. 以原目标名单为分母，逐对象查询并去重。额外对象、重复对象、跨企业或版本不匹配先报冲突；不取其中较好的一条覆盖冲突。未返回的对象记 unknown。
3. 区分平台受理、排期、已发送/已发布/邀请已出站、客户已读/入群/成交。排期保存成功仍是 pending；群邀请出站不证明入群。失败需实际失败证据；没有结果不是失败。
4. 按[结果契约](references/receipt-contract.md)整理回执。可运行 `python3 scripts/reconcile.py /客户工作区/receipt.json` 校验格式和计数。脚本只检查输入一致性；Agent 仍须回读引用的原始证据，不能用任意文件名充当成功证明。
5. 输出计划数与 succeeded、failed、pending、unknown、cancelled、expired 六类互斥计数，附逐对象状态、原任务引用和下一步。任务排期结束后仍须再次查询实际结果；核对结果不会改变授权。
6. 将失败、未知与冲突交给负责人；任何再次提交都回到原执行技能按[授权规则](../private-domain-ops/references/authorization.md)判断，不能由本技能自动重试。反馈交给 [sales-review](../sales-review/SKILL.md)。

没有业务连接时，可运行 `python3 scripts/mock_scrm.py --demo` 检查模拟批量流程。该命令使用临时本地数据库，不联网，输出始终标注 simulation。模拟通过不证明客户平台支持幂等或查询。
