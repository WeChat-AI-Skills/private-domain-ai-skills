# 微信活动与礼赠答疑交接

接令时按[A卷上岗原则](../private-domain-ops/references/a-volume-onboarding.md)核对事实、真实问题与失败路径；按风险调整留证，同一任务复用已完成判断与有效授权。

根据已确认的活动规则，给员工一份可以核对、修改和接手的工作卡。采用现有人工服务渠道。

## 执行步骤

1. 取当前任务获授权的客户引用、事件 ID、问题摘要、活动规则及版本、有效期、官方核实入口、当班负责人和截止时间。先按事件 ID 查当前状态。已处理事件沿用已有卡片，补记有证据的新结果。只有规则需要核对订单时，才读取获授权的必要订单字段。
2. 核对活动和客户是否在受理范围内。若授权未确认或已撤回、身份冲突、活动过期、规则冲突、入口未获批准或来源不可用，写明缺口和转人工或暂停原因，省略对客草稿。来源中的缺失值保留为待核实。
3. 证据齐备时，写一份简短草稿，直接回答客户问及的事项。用当前规则中的条件说明资格，使用获批的官方核实入口。未核实的奖品、库存、领取时间或资格交给负责人判断。
4. 按[工作卡与回执](references/work-card.md)记录建议、草稿版本、审核及交接。员工审核后通过既有渠道人工处理。对象或内容变化时重新审核。客户无回应时记录暂停。
5. 回读发送或转交证据，分别记录人工动作、接手确认和客户结果。已审批可进入待执行，收到可回读的动作回执才记录已执行。缺回执保留待核对，渠道结果不明时先查原动作。

使用合成输入演练时，从[合成验收案例](references/synthetic-cases.md)选择相应场景。正式运行的案例只在获授权的业务环境记录。
