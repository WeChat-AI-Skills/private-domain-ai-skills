# 运营复盘与规则提炼

输入：统计窗口与时区、任务与逐对象回执、获授权的正反案例、实际可用的订单数据、现有规则及版本。

1. 先逐对象核对，再汇总成功、失败、待执行和结果待核。名单重复、统计窗口或分母不同先处理差异；缺数据保留 null 及原因。
2. 平台受理、实际发出、客户阅读、回复、同意、入群、订单分别记录。无订单接入写“成交数据未接入”，不填零或推定成交。
3. 对变化检查样本、季节、活动、渠道与客群差异。遵守[证据规则](references/evidence.md)：客户自述和前后变化可以提供线索，不能单独证明普遍因果。
4. 用[规则卡](references/rule-card.md)提出新增、修改或下线建议：触发条件、动作、例外、证据与反例、适用范围、观察指标、负责人、版本和回滚条件。
5. 证据少时可提出待验证假设。样本数量不自动赋予高置信度；没有统一的“几例即可正式生效”门槛。
6. 写回规则或修改自动化需相应授权和实际入口，遵守[授权规则](../private-domain-ops/references/authorization.md)。建议、已审批、已写入和已生效分别回读。

输出：执行事实、经营数据可用范围、观察与限制、规则候选、需补证据、下一轮动作。真实案例留在客户工作区；仓库反馈使用合成或充分脱敏资料。
