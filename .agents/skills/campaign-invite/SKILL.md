# 活动邀请与群衔接

输入：活动目的、绝对时间及时区、形式与容量、已批准权益、客户池、筛选规则、目标群及负责人。

1. 按[筛选与分层](references/segmentation.md)明确资格与排除规则，使用稳定客户 ID 去重。只有汇总人数或模糊交集时，给可核实的范围与缺口，不编精确名单。
2. 输出互斥的纳入、排除、观察、待核集合及计数。排除项保留原因；多重标签选一个主邀约层，保留其他标签作为依据。
3. 分层起草邀约：为什么邀请此人、能解决什么、活动时间。权益、名额、留货、演示安排和视频服务只使用已核实资料。
4. 邀约发送按[授权规则](../private-domain-ops/references/authorization.md)与 [SCRM 好友消息](../wechat-scrm-friend-message/SKILL.md)执行；需要客户同意时记录同意证据，再由 [SCRM 现有群邀请](../wechat-scrm-group-invite/SKILL.md)衔接。
5. 未回复不视为同意；同意不证明已入群。重试前查原出站与成员记录。新建群、直接加人、群公告、移出成员和解散群均需对应授权与能力。
6. 按[群议程](references/run-of-show.md)准备活动安排。活动后分别核对邀请、同意、入群、到场、订单，逐层写统计窗口、去重口径和数据缺失。
7. 形成下一步候选：待补邀请结果、已同意未入群、未答问题、获授权的后续跟进。不要自动重发链接或启动回访。

输出：名单及依据、分层文案、议程、各阶段实际状态、异常和负责人。只有计划时标“拟邀约”，不填写“已邀约”。
