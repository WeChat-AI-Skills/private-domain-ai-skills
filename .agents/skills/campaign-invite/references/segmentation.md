# 筛选、分层与计数

先明确活动解决什么问题、什么证据符合资格、哪些对象排除、统计时间范围。示例筛选条件需按实际活动批准，不默认使用固定天数。

1. 核对稳定客户身份及归属；同昵称或“有订单”不足以证明同一个人。
2. 形成去重客户全集，拒联、身份待核、投诉或不适用权益按实际规则处理。
3. 纳入、排除、观察、待核四组互斥；合计应等于已核对的全集。
4. 同时满足多个邀请层时按已确定优先级选主层；保留多标签，但每人本次仅一个邀请计划。
5. 汇总数字无法确定交集或排除对象归属时，不计算精确去重数或邀约数；请求所需的最少 ID 与集合信息。

邀约、同意、入群、到场和订单各有独立证据。未发生时填“未执行/尚无结果”，不能把候选人数放入“已邀约”。分母为零或未知时不算比例。预期转化率须来自相应历史依据，不内置承诺。

活动后的标签或待办写回需要授权和入口；没有入口时输出变更建议。
