# 有赞加购未购排查

接令时按[A卷上岗原则](../private-domain-ops/references/a-volume-onboarding.md)核对事实、真实问题与失败路径；按风险调整留证，同一任务复用已完成判断与有效授权。

把“加购人群”和“同期已购人群”当作两份独立事实表，先核验窗口与导出条件，再在本机私域内精确匹配。不要把商品维度 `add_cart_uv` 求和当成店铺去重加购人数。

## 先读

执行前读取 [references/youzan-data-contract.md](references/youzan-data-contract.md)。需要后台导出时，使用当前环境已获授权的浏览器或有赞只读工具。只有用户在当前任务中明确同意客户数据协议和导出，才能点击“同意协议并导出”。

## 窗口口径

按 `Asia/Shanghai`、左闭右开区间计算：

- 昨天：前一个完整自然日 `[D-1 00:00:00, D 00:00:00)`。
- 过去 7 天：不含今天的 7 个完整自然日 `[D-7 00:00:00, D 00:00:00)`。
- “未购买”只表示同一窗口内没有已购记录，不表示客户历史上从未购买。
- 历史回溯任务不能用 CRM 的“上次消费时间”代替窗口内订单；此时必须改用覆盖完整窗口的有赞订单 API/明细，并取得能与加购人群精确相连的稳定客户标识。

## 标准工作流

### 1. 核验并下载加购人群

1. 在客户列表设置固定的 `lastAddCartTimeStart` 与 `lastAddCartTimeEnd`，确认页面总人数。
2. 打开导出确认页，检查是否明确带出加购条件或已保存人群名称。
3. 下载后统计原始行数、唯一客户数、缺少匹配键人数。
4. 将页面人数传给脚本的 `--ui-count`。页面人数与导出唯一客户数不一致时立即停止。

不要把名称写着“昨天”的滚动人群当成自然日事实。`近1天` 是滚动窗口；固定自然日是日历窗口，两者可能不同。

来源可用条件如下。

- 导出记录明确保存加购窗口，且文件唯一人数等于页面人数。
- 已核实固定日期定义和快照时间的客户分群，且文件唯一人数等于刷新后的分群人数。
- 已授权的客户级购物车事件事实表或 API，包含事件时间和稳定客户标识，同时提供已核对的来源人数作为 `--ui-count`。

若导出记录丢失加购条件，即使人数相同也停止，标记 `blocked_addcart_export_filter_dropped`。人数不符时标记 `blocked_ui_export_mismatch`。复用现有已确认的接口定义。

### 2. 下载同期已购客户

当前滚动窗口可在客户列表使用“上次消费时间”设置同一开始、结束时间并导出。确认页必须明确显示该时间范围；下载后再次校验每行“上次消费时间”均落在窗口内。

需要支付事件级精度、历史回溯或订单金额/商品时，改用有赞云只读订单 API 或订单明细导出。订单侧必须提供与加购侧相同的稳定客户 ID，或经过授权的完整手机号；否则停止，不用昵称、姓名、模糊手机号或收货人姓名猜测。

### 3. 本机去重并排除已购

优先使用双方共有的稳定客户 ID；没有时才使用双方共有的完整授权手机号：

```bash
python3 scripts/audit_youzan_cart_nonbuyers.py \
  --audience /private/path/cart-audience.zip \
  --paid-customers /private/path/paid-customers.zip \
  --window-start '2026-07-17 00:00:00' \
  --window-end '2026-07-18 00:00:00' \
  --ui-count 3
```

以上命令使用示例路径和人数，请按来源替换。默认只输出聚合摘要。校验通过且确需生成名单时，显式写入仓库之外的授权目录：

```bash
python3 scripts/audit_youzan_cart_nonbuyers.py \
  --audience /private/path/cart-audience.zip \
  --paid-customers /private/path/paid-customers.zip \
  --window-start '2026-07-11 00:00:00' \
  --window-end '2026-07-18 00:00:00' \
  --ui-count 3 \
  --write-private-output \
  --output-dir /private/path/youzan-cart-audit
```

若输入是内部客户 ID 列，增加：

```bash
--key-type id --audience-key-column yz_uid --paid-key-column yz_uid
```

成功要求输出 `status: ok`。诊断开关用于定位缺项，带警告的结果只作诊断。`--paid-time-column` 用于指定已购文件的实际时间列，订单明细应指定支付时间列。

### 4. 验收

必须同时满足：

- 导出唯一客户数等于页面总人数。
- 加购名单和已购名单分别完成去重。
- 已购文件的时间字段全部落在目标窗口。
- 匹配键无缺失、无掩码；否则输出“待核实”，不计入已验证未购。
- `已购排除人数 + 已验证未购人数 = 唯一可匹配加购人数`。
- 结果只保存在本机私域；不在聊天中展示姓名、手机号、微信号或客户 ID。

## 输出口径

最终只汇报聚合事实：窗口、页面人数、导出唯一人数、重复数、缺键人数、同期已购排除人数、已验证未购人数和阻断原因。把 CRM“上次消费时间”结果标成“同期已购代理口径”；只有支付事件或订单事实才能标成“支付人数”。

## 安全边界

- 默认只读与聚合；不自动触达客户、不打标签、不创建营销任务。
- 私密 CSV 权限设为 `0600`，目录设为 `0700`。
- 不读取或打印 API key、token、cookie、`.env`、日志或原始客户隐私值。
- 不把生成的客户文件放进 Git 仓库、飞书公开文档或普通项目目录。
- 任何人数不一致、时间条件缺失、稳定键不连通都必须失败关闭。
