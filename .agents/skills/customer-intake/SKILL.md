# 一对一接待与需求识别

输入：获授权的客户原话、稳定客户引用、可用的商品与服务规则、相关历史记录。缺库存、价格或物流资料时列出待核项。

1. 识别场合、预算、偏好、品类，保留限定词。“500 左右”按近似预算记录，不改成“500 以内”；提问顺序不能证明客户是否价格敏感。
2. 根据当下问题选必要追问。通常先问一至两个会改变推荐或承诺的问题；已明确的信息不重复问。客户询问库存而库存未知时，说明需核实。
3. 推荐只使用当前可核对的 SKU、价格、尺码、库存及服务条件。用户没有提供的评价、卖点、面料比例、留货或到货承诺不进入草稿。
4. 阶段判断注明证据与置信度。询价、短回复或沉默不自动等同购买意愿、拒绝或营销许可。
5. 按店铺语气给简短草稿及下一步。投诉、客户要求真人或超授权决定，按[交接卡](../private-domain-ops/references/handoff.md)处理。
6. 本次要求实际发送时，遵守[授权规则](../private-domain-ops/references/authorization.md)，由已适配通道或 [SCRM 好友消息](../wechat-scrm-friend-message/SKILL.md)执行并回读；只要求拟回复时交付草稿。

输出：客户引用、已知、推断及依据、待确认、建议回复、下一步、当前状态。需要记录档案时衔接 [customer-profile](../customer-profile/SKILL.md)。

按需参考[追问库](references/question-bank.md)与[回复模式](references/reply-patterns.md)。话术中的商品、时间与服务条款均需替换为当前事实。
