# 期望输出
```markdown
【客户】A（老客，买过牛仔裤）
【已知】场合：周末活动 · 预算：500 · 偏好：腰部宽松 · 品类：裤装
【推断】更在意舒适与版型，不是纯价格敏感（依据：先给预算，再提"腰部宽松"）
【待确认】收货城市——决定周六前能否到
【阶段】高意向（问预算 + 明确场景 + 老客）
【建议回复】
> 收到～周末活动穿、腰部宽松、500 内，我先帮您挑 3 条。
> 您收货城市是哪里？我核对下周六前能不能送到。
【动作】追问城市 → 核对时效 → 推荐 P01/P02/P03 → 写入档案
【风险】时效未确认，不能说"能到"；P03 偏厚，周末活动可能不合适
【授权】A（草稿）/ B（发送需确认）
```

## 客户回复"杭州"之后

```markdown
【时效】杭州，周五可送达，满足周六使用
【推荐】
① P01 高腰直筒 359：腰头加宽 2cm，最贴合"不勒腰"，通勤也能穿
② P02 微阔九分 399：松紧腰，垂感好，活动拍照更出片
③ P03 加绒直筒 459：怕冷选，但偏厚，周末室内活动可能热
【建议回复】
> 杭州周五能到，来得及。
> 按您说的腰部宽松，我倾向 P01：腰头加宽 2cm，坐着不勒；
> 想要更垂一点就 P02。您平时穿 M 还是 L？
【下一步】确认尺码 → 下单 → 周六前发货
【档案增量】城市:杭州 · 标签「行为:夜间咨询」「需求:周末活动」 · 待办:确认尺码
```

## 这个例子在演示什么

1. **先拆需求，再推荐**：一句话拆成四个字段，缺的那一项（城市）单独问；
2. **只问一个关键问题**：城市会改变"能不能承诺"，优先于颜色、搭配；
3. **不承诺未确认的事**：物流没查之前，不说"能到"；
4. **推荐不超过 3 个**，每个一句差异，最后给倾向；
5. **深夜不追加**：只回当前这一条，次日晨报再跟进。
