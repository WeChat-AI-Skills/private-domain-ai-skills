# 如何判断这个版本能做到哪一步

工程验证、客户现场验证和客户评分分别记录，不合并成一个“通过分”。

| 证据 | 可以说明 | 不能说明 |
| --- | --- | --- |
| 结构、脚本和合成测试 | 指定输入下的目录、字段约束、记录关联与计算符合预期 | 所有 Agent 都会正确判断，或真实平台已适配 |
| 完整包安装与宿主发现 | 该版本文件可复制、升级回退且指定宿主识别技能 | 客户账号连接、真实业务执行或业务价值 |
| 独立 Agent 合成行为 | 隔离输入下，本次作答是否遵守关键边界 | 其他宿主、模型或未来每次作答均正确 |
| 客户现场执行与回读 | 指定环境、账号、对象、动作及时间下的实际结果 | 未覆盖动作或其他企业也能运行 |
| 客户验收与评分 | 客户对实际交付的独立判断 | 工程检查、独立审查或跨场景有效性 |

公开的版本验证只使用合成或脱敏材料，报告测试版本、范围、失败与未验证项。客户现场回执留在客户工作区；目录内的 `live_status: not_verified` 不能被一次本地模拟改成现场成功。

任务卡检查器读取明确提供的 JSON 证据包，核对任务、范围、版本、时间、审查结论与恢复计划。引用、角色名和自报身份不是认证凭据；检查结果也不会签发业务权限、调用工具或接管执行。具体时间与就绪语义以[任务约定](../.agents/skills/private-domain-ops/references/contracts/task-and-result.md)为准。

自评、独立审查和客户评分分别保存；未收到客户评分时保持未评分。本版记录见 [v1.2.2 验证](verification-v1.2.2.md)。
