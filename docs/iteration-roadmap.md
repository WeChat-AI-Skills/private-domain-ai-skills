# 能力目录与迭代路线

当前版本 v1.3.0，保留原 15 项技能，新增 SCRM 操作包，共 16 项。产品目录采用[七类能力与 28 节点](skill-tree-overview.md)：上岗与编排、客户意图判断、发朋友圈、一对一聊天、拉群、上架、复盘。

## 本版本

新增 `wechat-scrm-operator`，交付工具/会话检查、SCRM 页面操作档案、客户绑定模板和离线调用/回执核验。按客户任务从当前真实工具进入系统，先图文朋友圈和任务式好友消息；不把配置检查当接入成功。安装包先发布，现场验证按下节推进。

延续 A卷三关和六个角色重点关、任务/结果契约 1.2、可关联的审查恢复签核记录、10 个随包失败案例和技能就近停止条件；保持旧 1.0/1.1 卡片读取兼容。商品、互动等后续独立技能尚未创建，不能当成已安装能力。

建立总控与五个专业角色职责、机器目录、三条工作流、任务和结果约定、最小上下文规则、随包合成演练与目录工具。运行必需资料随总控技能复制，单会话按角色执行是默认模式。

安装协议仍为 registry 1.0，保留旧六域登记用于兼容，产品导航使用 product_catalog。角色、节点与技能间的引用由架构校验器检查，生成文档与源目录保持一致。现场状态仍按[能力状态](capability-status.md)单独验收。

## v1.3.0 客户现场验收（仍待完成）

在客户提供实际入口和明确授权后，验证上岗 → 一条朋友圈 → 实际发布 → 结果核对 → 复盘。复用已有授权及规则，保留原任务和逐账号证据。超时查原任务，未到时间只记排期，失败与未知单列。

该链路不要求先实现完整商品上架或常驻多 Agent 系统。

第二条链路验证指定好友的有限任务消息与实际出站；聚合聊天即时回复另建适配。后续版本按实际需求扩展素材类型、自动化规则、更多产品及 API/MCP/CLI；同能力可选择不同实现，提交后状态未知时不跨实现重发。

## 后续按客户任务补充

| 方向 | 可验收的下一步 |
| --- | --- |
| 客户意图判断 | 统一事实、推断、未知、顾虑、下一步与失效条件；验证后再决定独立为 customer-intent |
| 商品资料与上架 | 先验证 product-catalog 的资料与当前价格库存，再考虑 product-listing；均为候选，真实平台执行另行验证 |
| 朋友圈互动 | 验证评论读取、稳定身份与私信衔接后，再决定 moments-engagement |
| 群内服务 | 先验证 group-operations 的欢迎与答疑草稿，实际群消息执行与回读另行适配 |
| 真实宿主分派 | 在需要并行的任务中验证上下文隔离、依赖和结果回传 |
| 组织大脑与持续运行 | 按实际需要实现查询、并发控制、调度与监控，不把角色文件当运行服务 |

新能力需有独立输入、输出及证据才进入安装清单，不以技能或 Agent 数量衡量进度。真实案例留在客户工作区，反馈提炼为合成或充分脱敏案例。规则候选验证并获授权生效后，保留版本和回退条件。
