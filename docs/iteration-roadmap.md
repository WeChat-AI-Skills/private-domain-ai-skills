# 能力目录与迭代路线

当前版本 v1.1.0，15 个技能入口。采用“先能安装、再能识别、再能在客户环境执行和核对”的验收顺序，每一步保留独立证据。

## 六个业务域

| 业务域 | 已有入口 | 后续根据实际任务补充 |
| --- | --- | --- |
| 上岗与编排 | private-domain-ops、wechat-scrm-onboarding | 客户平台能力探测及真实异常恢复 |
| 客户理解 | customer-intake、customer-profile | 商品匹配、异议处理场景及带版本写入适配 |
| 跟进经营 | followup-plan、wechat-scrm-friend-message、wechat-scrm-friend-cleanup | 已购回访、复购与沉睡唤醒配置 |
| 内容运营 | moments-calendar、wechat-scrm-moments | 素材工具适配、互动与私信衔接 |
| 活动运营 | campaign-invite、wechat-scrm-group-invite、wechat-activity-customer-handoff、audit-youzan-cart-nonbuyers | 群内议程执行和完整漏斗查询 |
| 结果与学习 | task-reconcile、sales-review | 日报、经营经验候选规则与验证 |

能力节点可由技能内部步骤、参考资料或工具实现；只有明确独立输入、输出与可验收行为时才增加技能。上岗沿用现有 wechat-scrm-onboarding 名称，避免新增同义入口。

## 下一轮：第一条客户现场链路

1. 用客户批准的只读入口完成环境卡，核对租户、工作号、权限与查询能力。
2. 选一条明确授权的朋友圈，确认图文、账号、时间、规则和实际任务 ID。
3. 回读排期；到期按账号查询发布结果，失败或未知走原任务核对与人工接管。
4. 记录现场失败及脱敏复现，把缺陷变成案例，再发布补丁版本。

真实接口文档、测试账号和客户授权具备后才能推进对应动作。当前没有承诺接口适配时间、自动化已启用或经营效果。

## 协作安排

每次迭代可按技能内容、接入代码、验证拆任务；独立文件可并行，共用规则和版本由一个集成人维护。任务卡记录目标、输入、允许修改的文件、验收和交接产物。独立评测只给请求、技能及最少原始材料，不给标准答案。

固定“主 Agent + 5 个角色”作为扩展建议保留，具体人数按可用宿主与实际任务决定；不为角色数量建立空任务。评测通过与客户业务验收分别记录。

## 机器可读登记

[manifest.json](../manifest.json) 为安装和登记的唯一清单。dependencies 表示完整安装包中的跨技能引用，允许编排互相引用，不是必须执行的顺序。resources 列出随技能复制的文件；execution_kind 区分流程指南、编排和本地脚本，不能从 guided 推断已接通 SCRM。live_status 当前统一为 not_verified，验证证据链接说明实测范围。

客户的配置、授权、回执、原始聊天和凭据仍存客户工作区，不并入发布包。反馈提炼为脱敏案例和规则候选，规则生效需覆盖该变化的授权。
